**ПМ4 «Разработка REST API»**

# ТЕХНИЧЕСКОЕ ЗАДАНИЕ НА КУРСОВУЮ РАБОТУ

Разработка серверного приложения с REST API на Node.js, Express, Prisma ORM и PostgreSQL

Специальность: 06130100 «Программное обеспечение (по видам)»

Квалификация: 4S06130105 «Техник информационных систем»

*Статус: проект; параметры утверждения, сроки и тема уточняются руководителем курсовой работы.*

## 1. Цель проекта

Самостоятельно разработать документированный REST API по выбранной предметной области, демонстрирующий работу с HTTP, организацию серверного приложения, взаимодействие с реляционной базой данных, проверку входных данных и обработку ошибок.

## 2. Выбор темы

Студент самостоятельно выбирает тему из предложенного перечня либо предлагает собственную и согласовывает её с преподавателем. Тема должна предусматривать разработку REST API для решения конкретной прикладной задачи, включая хранение и изменение данных в реляционной базе данных. Приведённые примеры не ограничивают количество и состав сущностей.

- Система управления библиотекой — учёт книг, авторов, жанров и экземпляров.
- Система управления задачами — проекты, задачи, исполнители и статусы.
- API каталога товаров — товары, категории, характеристики и остатки.
- Система управления мероприятиями — мероприятия, площадки, участники и расписание.
- Система учёта личных финансов — доходы, расходы и категории операций.
- Каталог фильмов и сериалов — произведения, жанры, режиссёры и оценки.
- Система учёта оборудования — устройства, места размещения и история перемещений.
- Система записи на занятия — занятия, преподаватели, расписание и записи обучающихся.

Примерный перечень тем не является исчерпывающим. Количество таблиц, их поля и связи должны быть обоснованы функциональностью выбранного API.

## 3. Обязательные требования (базовое задание)

### 3.1. Технологический стек

- Node.js, JavaScript (ES Modules), Express.js.
- PostgreSQL для постоянного хранения данных.
- Prisma ORM для описания моделей и операций с базой данных.
- Git и GitHub: исходный код доступен по ссылке на репозиторий.
- README.md с инструкциями по установке, запуску, настройке БД и использованию API.
### 3.2. Функции API

- Количество и состав сущностей определяются студентом по требованиям предметной области. Обязательный минимум — две взаимосвязанные таблицы с первичными ключами и хотя бы одним внешним ключом; верхнего ограничения на число сущностей нет. Искусственно увеличивать число таблиц не требуется.
- Полный CRUD для основной сущности: создание, получение списка, получение по идентификатору, частичное изменение, удаление.
- Для других сущностей набор операций выбирается в соответствии с логикой проекта. Необходимо предусмотреть как минимум чтение связанной сущности (список и/или объект по идентификатору).
- Хотя бы один запрос, возвращающий связанные данные через Prisma include или select.
- Все запросы и ответы используют JSON; URL ресурсов и HTTP-методы соответствуют REST-подходу.
- Валидация входных данных (обязательные поля, типы, допустимые значения), централизованная обработка ошибок.
- Корректные HTTP-статусы как минимум: 200, 201, 400, 404 и 500; ошибки внешних ключей обрабатываются осмысленно (например, 409).
### 3.3. Пример API (не обязательная тема)

| Метод | Маршрут | Результат |
| --- | --- | --- |
| GET | /api/products | Список товаров |
| GET | /api/products/:id | Один товар или 404 |
| POST | /api/products | Создание, 201 |
| PATCH | /api/products/:id | Частичное изменение |
| DELETE | /api/products/:id | Удаление |
| GET | /api/categories | Список категорий |
| GET | /api/categories/:id | Категория по ID |

### 3.4. Структура и воспроизводимость

- Логика разделена минимум на маршруты (routes), контроллеры (controllers), сервисы (services) и конфигурацию Prisma; разделение ответственности соблюдено.
- В репозитории должны находиться prisma/schema.prisma и способ воспроизведения структуры БД (миграции или подробная инструкция для существующей схемы). ER-диаграмма БД с сущностями, полями, ключами и связями обязательна и в пояснительной записке, и в README.md.
- Есть начальные тестовые данные или инструкция их внесения; проект можно развернуть по README на другом ПК.
- Учётные данные не хранятся в репозитории: DATABASE_URL задаётся через .env, пример переменных находится в .env.example; .env и node_modules исключены через .gitignore.

В пояснительной записке ER-диаграмма помещается в раздел проектирования базы данных с пояснением назначения таблиц и отношений. В README.md та же актуальная схема размещается в разделе «Структура базы данных»; изображение хранится в репозитории (например, docs/erd.png).

### 3.5. Документация README.md

- Название, цель, тема и применённые технологии.
- Системные требования (Node.js, PostgreSQL), необходимые зависимости.
- Последовательность установки, заполнения .env, подготовки БД и запуска приложения.
- Описание всех endpoint: HTTP-метод, URL, параметры, пример JSON-запроса и ответа, ожидаемые коды ошибок.
- Обязательная ER-диаграмма базы данных (например, построенная в pgAdmin ERD Tool или другом редакторе на основе Prisma Schema), показывающая таблицы, первичные/внешние ключи и связи. Изображение должно быть включено непосредственно в README.md, а не только приложено файлом. Prisma Studio можно использовать для демонстрации записей, но его скриншот не заменяет ER-диаграмму.
- Описание проверки API (Postman, Insomnia, curl или аналог), пример работы хотя бы с одним полным CRUD-сценарием.
- Автор, дата/версия и ссылка на репозиторий.

## 5. Этапы выполнения

1. Выбор темы и согласование предметной области.
2. Проектирование сущностей в соответствии с темой, их атрибутов и связей; создание ER-диаграммы и перечня REST endpoint.
3. Создание проекта Node.js/Express и настройка PostgreSQL/Prisma.
4. Реализация сервисов, контроллеров и маршрутов.
5. Реализация проверки данных и HTTP-ошибок.
6. Проверка сценариев CRUD и связанных запросов.
7. Оформление README, публикация на GitHub.
8. Подготовка демонстрации и защита.
